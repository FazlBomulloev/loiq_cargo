**Направление:** A — тёплый минимал.
**Дата:** 2026-08-26.
**Основание:** `TZ_cargo_system.md` (v1) + утверждённый canvas

## 0. Границы решения

Что фиксируется здесь:

- палитра, типографика, spacing, радиусы, тени, motion;
- компоненты и их состояния;
- макеты экранов по ролям (клиент, склад Китая, Душанбе, овнер) и
  публичные экраны;
- паттерны данных (статусы, пилюли, пустые состояния, ошибки).

Что НЕ входит:

- дизайн бот-сообщений (текст в §14 ТЗ, форматирование сообщений
  задаётся в спеке бота отдельно);
- тёмная тема (структура токенов готовит её появление; палитра
  подбирается позже);
- дизайн PDF-документов (наследуют «печатный» слой §6 ниже —
  подробный шаблон отдельно, когда дойдём до выдачи).

## 1. Принципы

1. **Таблица — главный компонент.** Данные читаются, а не украшаются.
2. **Один акцент — терракот.** Всё остальное — тёплые нейтрали.
   Семантические цвета (good/warn/crit) обособлены и не считаются
   акцентом.
3. **Плотность как приоритет для склада, воздух — для клиента.**
   Одна и та же система, две плотности. Настраивается через
   `--row-h` и `--cell-x`.
4. **Статус в двух видах разом.** Всегда цвет + слово. Никогда только
   цвет.
5. **Печать — первого класса.** Ключевые документы (накладная,
   чек выдачи) выводятся на бумагу как настоящие бумаги. Печатный
   лист использует serif (Fraunces) как микро-отсылка к
   «товарной книге» из направления B.
6. **Роль решает, а не украшает.** Каждый экран отвечает за одну роль
   и один сценарий. Мультироль (например, овнер, работающий за
   склад Иу) переключается явно в шапке.

## 2. Токены

### 2.1 Цвет

Токены — семантические, не «имена цветов». Реализация — CSS
переменные на `:root`. Компоненты обращаются только к семантике.

| Токен | Значение | Роль |
|---|---|---|
| `--bg-app` | `#F5EFDF` | фон приложения |
| `--bg-elev` | `#FBF6EA` | второй уровень (тула, попапы низа) |
| `--bg-card` | `#FDFAF3` | карточки, панели, таблицы |
| `--bg-input` | `#FFFFFF` | поля ввода |
| `--bg-hover` | `#F0E7D3` | ховер по строкам и пунктам меню |
| `--text-primary` | `#1F1A15` | основной текст |
| `--text-secondary` | `#4A4238` | подпись, лейбл |
| `--text-muted` | `#8A7F6E` | мета, помощь |
| `--text-faint` | `#B7AC98` | плейсхолдеры, disabled |
| `--line-strong` | `#D9CFB9` | видимая линейка (шапка таблицы) |
| `--line` | `#E8DFCD` | обычная граница |
| `--line-hair` | `#F0E9D6` | «волосок» (между строк) |
| `--accent` | `#B45A2B` | основной акцент |
| `--accent-strong` | `#8F421D` | акцент при hover |
| `--accent-tint` | `#F1D6C4` | подсветка выбранного, focus-ring |
| `--good` | `#516F3A` | success |
| `--good-tint` | `#E6EDDA` | фон пилюли/бэджа good |
| `--warn` | `#A76A16` | предупреждение |
| `--warn-tint` | `#F6E7C8` | фон пилюли/бэджа warn |
| `--crit` | `#A63A2A` | ошибка/критическое |
| `--crit-tint` | `#F1D9D2` | фон пилюли/бэджа crit |
| `--info` | `#4C6580` | нейтральная информация |
| `--info-tint` | `#E1E7EE` | фон info |

Правила использования:

- любой текст, где важна читаемость, — только `--text-primary`,
  `--text-secondary` или на тинте — тёмный вариант того же цвета;
- статусные тинты используются ТОЛЬКО как фон пилюль/полосок,
  не как фон карточек;
- `--accent-tint` — единственная «мягкая» подсветка выбранного
  элемента, focus-ring и hover'ов у кнопок.

### 2.2 Типографика

Три шрифта, роли строго разведены.

| Роль | Шрифт | Fallback |
|---|---|---|
| UI-текст | Inter (400/500/600) | system-ui, Segoe UI, sans-serif |
| Цифры, коды, лейблы | IBM Plex Mono (400/500) | ui-monospace, Menlo, monospace |
| Печатный заголовок | Fraunces (500/600, opt. italic) | Iowan Old Style, Georgia, serif |

Fraunces — ТОЛЬКО в:

- заголовке накладной и чека выдачи (на экране и в PDF);
- H1 овнерского дашборда;
- крупных пустых состояниях (см. §5).

Везде остальное — Inter.

Шкала (rem, база 16 px):

| Токен | Размер | Line-height | Использование |
|---|---|---|---|
| `--fs-2xs` | 10 px / 0.625 rem | 1.4 | подписи в бэджах |
| `--fs-xs` | 11 px / 0.6875 rem | 1.5 | мета, IBM Plex Mono лейблы |
| `--fs-sm` | 12.5 px / 0.78 rem | 1.55 | тело таблиц, пилюли |
| `--fs-md` | 14 px / 0.875 rem | 1.55 | тело интерфейса (по умолчанию) |
| `--fs-lg` | 16 px / 1 rem | 1.55 | клиентские блоки чтения |
| `--fs-xl` | 20 px / 1.25 rem | 1.35 | H3, крупная цифра |
| `--fs-2xl` | 26 px / 1.625 rem | 1.25 | H2, статистика |
| `--fs-3xl` | 34 px / 2.125 rem | 1.1 | H1, заголовок раздела |
| `--fs-4xl` | 44 px / 2.75 rem | 1.05 | заглушки, пустые состояния |

Правила:

- `font-feature-settings: "ss01","cv11";` — включаем в
  `body { }` для одинарной `g`;
- `font-variant-numeric: tabular-nums;` — на всех колонках с
  числами, суммах, кодах;
- `letter-spacing` — по умолчанию 0; для uppercase-лейблов
  `.10em`–`.16em`; для H1/H2 — `−0.015em`;
- заголовки H1/H2 — `text-wrap: balance`.

### 2.3 Spacing

Шаг 4 px. Токены: `--s-1`=4, `--s-2`=8, `--s-3`=12, `--s-4`=16,
`--s-5`=20, `--s-6`=24, `--s-8`=32, `--s-10`=40, `--s-12`=48,
`--s-16`=64, `--s-20`=80.

- отступ карточки: `--s-6`;
- отступ строки таблицы (плотная): 10 × 8 → `--row-h: 40px`,
  `--cell-y: 10px`;
- отступ строки таблицы (клиент): 14 × 12 → `--row-h: 52px`,
  `--cell-y: 14px`;
- ширина колонки контента чтения: `max-width: 62ch` для текста
  и `72ch` для сумм.

### 2.4 Радиусы

| Токен | Значение | Использование |
|---|---|---|
| `--r-0` | 0 | сеточные линии в таблицах, разделители |
| `--r-1` | 2 px | пилюли, бэджи |
| `--r-2` | 4 px | инпуты, чипы |
| `--r-3` | 6 px | кнопки, карточки, поля |
| `--r-4` | 10 px | попапы, модалы |
| `--r-full` | 999 px | круглые пилюли статусов |

### 2.5 Тени

Тёплые, ненасыщенные — не используются для «глубины», только для
«поднятия» над бумагой.

- `--shadow-hair`: `inset 0 -1px 0 var(--line-hair)` — низ шапки;
- `--shadow-card`: `0 1px 0 rgba(180,90,43,.03), 0 4px 12px -8px
  rgba(80,50,20,.14)` — карточки;
- `--shadow-pop`: `0 6px 24px -10px rgba(80,50,20,.22)` — модалы,
  выпадающие;
- `--shadow-focus`: `0 0 0 3px var(--accent-tint)` — focus-ring.

### 2.6 Motion

`--dur-fast: 120ms`, `--dur-med: 200ms`, `--dur-slow: 320ms`.
Эйзинг `--ease: cubic-bezier(.2,.6,.2,1)`. Всё уважает
`prefers-reduced-motion: reduce` → отключение анимации, оставляем
только цвет.

Разрешено:

- fade + 4 px shift на попапах и тостах;
- смена цвета пилюли/бэджа при переходе статуса;
- hover-подсветка кнопки/строки;

Запрещено:

- параллаксы, «прыгающие» элементы, спиннеры-псевдо-3D;
- анимация цифр при обновлении — только явный toast.

## 3. Иконки

Единственный набор — **Lucide** (outline, 1.5 px stroke). Размер
16 px в UI, 20 px в шапках, 32 px в пустых состояниях. Иконки
используются, только когда добавляют смысл: статус, действие,
навигация. Никогда как декор.

Не используем emoji в интерфейсе (в бот-сообщениях можно —
это уже канал).

## 4. Компоненты

Каждый компонент описывается: назначение → анатомия → состояния →
токены. Полные визуальные образцы вошли в canvas-артефакт; ниже
только контракт.

### 4.1 Button

Варианты: `primary`, `secondary`, `ghost`, `danger`.
Размеры: `sm` (h 28), `md` (h 36 — по умолчанию), `lg` (h 44).

- primary: bg `--accent` → hover `--accent-strong`, text
  `#FDFAF3`, radius `--r-3`.
- secondary: bg `--bg-card`, border 1 px `--line`, text
  `--text-primary`.
- ghost: без фона, text `--text-secondary`, hover bg `--bg-hover`.
- danger: как primary, но `--crit`.

Состояния: default → hover → focus (`--shadow-focus`) → active
(bg darken 4%) → disabled (opacity .5, cursor not-allowed) →
loading (spinner 12 px справа, кнопка не блокируется визуально
кроме disabled-состояния).

Никаких иконок «для красоты» слева. Иконка перед текстом только
если действие сложно передать словом («+ Приёмка»).

### 4.2 Input / Textarea

- h 36, padding 8 × 12, bg `--bg-input`, border 1 px `--line`;
- focus: border `--accent`, shadow `--shadow-focus`;
- ошибка: border `--crit`, подпись под полем `--fs-xs`
  `--crit`;
- обязательные поля не помечаются звёздочкой — помечаем
  необязательные меткой `(опц.)`;
- числовые поля используют IBM Plex Mono + `text-align: right`
  когда рядом с единицей.

### 4.3 Select / Combobox

Единый механизм для склада, статуса, роли, клиента. Всегда
показывает выбранное + иконку `▾`. Открывается popover с поиском
для наборов >8 элементов. Клавиатура: `Enter` выбирает,
`Esc` закрывает, `↑/↓` навигация.

### 4.4 Table

Универсальный компонент. Отвечает за:

- шапку `sticky` при скролле;
- сортировку кликом по заголовку (⇅ / ↑ / ↓);
- отметку строки чекбоксом (для приёмки Душанбе, оптимизатора);
- три плотности: `dense` (склад), `regular` (по умолчанию),
  `airy` (клиент);
- пустое состояние в теле (см. §5).

Шапка: `--fs-xs` uppercase, IBM Plex Mono, `letter-spacing .1em`,
низ отделён `--line-strong`.

Строки: разделитель `--line-hair`. Hover — `--bg-hover`. Клик по
строке открывает деталь в drawer'е справа (не переход на новый
экран), кроме таблиц выдачи — там выделение остаётся.

### 4.5 Pill / StatusBadge

Одна геометрия, семь семантических вариантов:

| Код | Фон | Текст | Пример |
|---|---|---|---|
| `neutral` | `#F0E7D3` | `--text-muted` | «на складе» |
| `route` | `--accent-tint` | `--accent-strong` | «в пути» |
| `ok` | `--good-tint` | `--good` | «принято», «готов к отправке» |
| `warn` | `--warn-tint` | `--warn` | «без клиента», «недобор» |
| `crit` | `--crit-tint` | `--crit` | «горит», «недостача», «перегруз» |
| `info` | `--info-tint` | `--info` | «выдан», «архив» |
| `outline` | прозрачный | `--text-primary` | нейтрально-акцентный |

Точка перед текстом того же цвета — всегда. Форма: `--r-full`,
padding 3 × 8, `--fs-2xs`, weight 500.

Отдельная разновидность для «горящий N дней»: pill `crit` +
хвост с числом IBM Plex Mono — `горит · 21 д`.

### 4.6 Chip (для фильтров)

Как Pill, но кликабельный, с состояниями active/inactive.
Отличие от Pill в жирности: chip active — bg `--accent-tint`,
text `--accent-strong`.

### 4.7 Card

Anatomy: header (title + меню) → body → footer (опц.).
`background: --bg-card`, `border: 1px --line`, `radius: --r-3`,
`shadow: --shadow-card`. Заголовок — Inter 600 `--fs-lg`.

### 4.8 Tabs

Табы под линией. Активный — жирный, снизу линия `--accent`
толщиной 2 px. Никаких «капсульных» табов.

### 4.9 Drawer

Панель справа, ширина 460 px, для деталей выбранной строки.
Не блокирует остальной интерфейс до полной ширины. Внутри —
Card без внешней тени.

### 4.10 Modal

Центрированный, для действий требующих подтверждения
(отменить приёмку, применить заявку сотрудника). Ширина 480 px.
Максимум два действия в футере: primary справа, ghost «Отмена»
слева.

### 4.11 Toast

Появляется снизу-справа, ширина 320 px, 4 варианта (info, ok,
warn, crit). Живёт 5 сек, интерактивные держатся до закрытия
(например «Заявка отправлена — Отменить»).

### 4.12 Empty state

Три класса пустоты:

- **чистый первый вход** (нет данных вообще) — иллюстрация одной
  линией + предложение действия;
- **пустой фильтр** — «Ничего не найдено» + сброс фильтров;
- **пустой список после успеха** (например, все партии закрыты) —
  без иллюстрации, только сообщение.

Иллюстрации — SVG в терракоте, максимально условные (коробка,
фура, документ). Заголовок Fraunces `--fs-2xl`, подпись Inter
`--text-muted`.

### 4.13 Toolbar фильтров

Единая полоса над таблицей: поиск (`Cmd/Ctrl+K`), фильтры-чипы,
секция сортировки, действие справа. Плотность как у таблицы
под ней.

### 4.14 KPI (стат-плитка)

Для дашборда: `--fs-2xl` число (Inter 600, tabular-nums),
`--fs-xs` uppercase лейбл, дельта под цифрой (маленькая
стрелка + число, семантический цвет). Никаких «графиков внутри
плитки» — sparkline допустим только если отражает данные из
запроса, а не заглушку.

### 4.15 Форма приёмки (специализированный)

Компонент из четырёх полей: код клиента (Combobox), описание
(Input, опц.), объём (Input число, м³), вес (Input число, кг).
Ниже — предпросчёт плотности и предполагаемой стоимости
(маленькая карточка, реюзается из калькулятора). Кнопка
«Сохранить» в основании.

### 4.16 Плотностный трек (оптимизатор)

Горизонтальная полоса из 3 сегментов (плотное / среднее / лёгкое)
с цветовой градацией акцента. Ширина сегмента = доля объёма.
Ниже — легенда с процентами и «цель 40 / 35 / 25». Каждая
«ворота» (§9 ТЗ) — карточка `KPI` со семантическим цветом
`good`/`warn`/`crit` по факту прохождения.

## 5. Паттерны данных

### 5.1 Статусы товара

По ТЗ §5:

| Статус | Pill |
|---|---|
| на складе Китая | `neutral` — «на складе» |
| в пути | `route` — «в пути» |
| в Душанбе | `ok` — «в Душанбе» |
| выдан | `info` — «выдан» |

Флаги — отдельные пилюли, могут стоять рядом со статусом:

- горящий → `crit` — `горит · N д`;
- без клиента → `warn` — `без клиента`;
- недостача → `crit` — `недостача`.

### 5.2 Плотность и стоимость

Всегда показываем плотность (кг/м³) и рядом — тарифную ступень
из сетки склада. Стоимость — в сомони, но у овнера в тарифной
сетке значение в $ (по ТЗ §6). Формат чисел:

- вес — целое число, `кг`;
- объём — 2 знака, `м³`;
- плотность — целое, `кг/м³`;
- деньги — `12 480 c.` для сомони, `$28.4k` для сумм фуры,
  `$0.70/кг` для ставок сетки.

### 5.3 Пустые состояния — тексты

- «Товаров на складе Иу пока нет. Оформите первую приёмку.»
- «По фильтру ничего не найдено. Сбросить фильтры.»
- «Все партии закрыты. Отличная работа за сегодня.»

Никаких «упс», «ой», извинений в UI.

### 5.4 Ошибки

Форма: `--crit` линия слева карточки + короткое объяснение +
конкретное действие. Пример: «Не сохранилось: код клиента
LQ-9999 не существует. Проверить код или отметить приёмку как
"без клиента".»

### 5.5 Загрузка

- скелетоны для таблиц (3 строки, серые полоски);
- inline-спиннер 12 px в кнопках при action-загрузке;
- полноэкранный лоадер запрещён.

## 6. Печатный слой

Экранная система — Inter/sans. Печатный слой — Fraunces/serif с
той же палитрой, но:

- фон — белый (`#FFFFFF`), не кремовый (экономия чернил);
- линии — `#1F1A15` (полный чёрный);
- акцент штемпеля — `#7C1D1D` (тёмно-бордо) как микро-мостик к
  направлению B;
- шрифт заголовка — Fraunces 500;
- шрифт реквизитов — IBM Plex Mono;
- шрифт тела — Source Serif 4 или Fraunces regular.

Печатаются:

- **Накладная партии** (при отправке фуры) — заголовок «Накладная
  № LQ / N», реквизиты склада, таблица товаров, подписи;
- **Чек выдачи** — заголовок «Выдача LQ-NNN», список товаров,
  разбивка стоимости (фрахт + простой), сумма к оплате;
- **Тарифная карточка** склада (в помощь операторам) — сетка
  плотностей и ставок.

Все три — форматом A4, обязательно печатаются одинаково при
`window.print()`.

│                                                              │

## 9. Экраны склада Китая

### 9.1 Список товаров

## 12. Роль-специфичные акценты

- **Клиент** — оболочка мягче: воздух больше, кнопки меньше,
  контента больше на строку. Никаких «сотрудничьих» пилюль
  типа «без клиента» — только его собственные статусы.
- **Склад Китая** — плотный, cтабильный шапка = его склад,
  плотность строк максимальна.
- **Душанбе** — плотность средняя, документная эстетика
  выражена сильнее (накладные).
- **Овнер** — самая широкая шапка (переключатель склада +
  переключатель роли для тестирования взгляда «глазами
  сотрудника»).

## 13. Адаптивность

Брейкпоинты: 640 (m), 900 (t), 1200 (d).

- **клиент** — mobile-first, при 640 всё сжимается до колонки;
- **склад / Душанбе** — целевое устройство десктоп 1366+, но
  таблицы должны выживать в 1024 (горизонтальный скролл
  контейнера, не страницы);
- **овнер** — только десктоп.

Правило: страница НИКОГДА не скроллится горизонтально. Всегда
контейнер `.table-wrap { overflow-x:auto; }` или уменьшенная
плотность.

## 14. Доступность

- контраст: `--text-primary` на `--bg-card` — 15.3:1
  (проверить: WCAG AAA); `--accent` на `--bg-card` — 4.7:1
  (AA). Пилюли — фон-текст ≥ 4.5:1.
- вся навигация клавиатурой: `Tab` по естественному порядку,
  `Enter` активирует, `Esc` закрывает overlays;
- focus-ring — `--shadow-focus`, никогда не убираем;
- фокус-таргеты — минимум 44 × 44 на мобилке (клиент);
- `prefers-reduced-motion: reduce` → выключаем всю анимацию,
  оставляем состояния цвета;
- alt-тексты и aria-label для всех иконок-действий;
- цветослепые: статусы всегда дублируются словом и/или иконкой.

## 15. Открытые вопросы к дизайну

Пункты из §19 ТЗ + всплывшее из этого спека:

1. **Нумерация товаров клиента** (LQ-007-1, -2…) — до решения
   показываем только «код клиента + партия + дата приёмки»;
   если введём LQ-007-N — добавится колонка «№» перед описанием.
2. **Иконка бренда/логотип** — сейчас в макетах кружок-точка.
   Отдельный шаг: логотип-словомарка Fraunces 600 «Loik» с
   акцентной точкой над `i`. Уточнить.
3. **Печать накладной A4** — черно-белая или с бордо-штемпелем?
   По умолчанию — со штемпелем (одноцветный, экономный).
4. **Уведомления в веб-приложении** — нужны ли, кроме тостов?
   Пока нет: телега покрывает клиента, тосты — сотрудников.
5. **Роль-мультиплексор для овнера** — «смотреть как сотрудник
   Иу» — предусмотрен слотом в шапке; поведение (только чтение
   или полноценное действие) — решить.
